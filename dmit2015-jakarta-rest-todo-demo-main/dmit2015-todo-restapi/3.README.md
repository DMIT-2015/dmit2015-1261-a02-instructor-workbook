## Step 1 — Understand Swagger UI and OpenAPI

### What we're doing
The Swagger UI can be used to test REST APIs, just like in the Microsoft ASP.NET Core tutorial referenced by the lesson.

Two related technologies are involved:
| Technology | Purpose |
| --- | --- |
| Eclipse MicroProfile OpenAPI | Describes the REST API endpoints in a machine-readable format. |
| Swagger UI | Displays those endpoints in a browser and allows us to execute requests. |

WildFly's MicroProfile OpenAPI support can generate an OpenAPI document based on the REST resource classes in our application.

The URL provided in the reference document is:
```text
http://localhost:8090/openapi?format=JSON
```


“OpenAPI describes our REST API endpoints.

Swagger UI reads that description and creates a user interface for testing them.

Instead of manually typing every HTTP request, we can choose an endpoint, click Try it out, provide values, and click Execute.

We can still use IntelliJ's HTTP Client, but Swagger UI gives us another way to interact with the API.”

“Swagger UI initially points to the Petstore sample API.

## Step 6 — Understand the CORS error

### What we're doing
Before adding the filter, let's understand why the browser blocks the request.

CORS stands for Cross-Origin Resource Sharing.

An origin is determined by the protocol, hostname, and port. When JavaScript running from one origin requests data from another origin, the browser checks whether the server permits that access.

For example, Swagger UI opened from a local file and the REST API running at http://localhost:8090 do not have the same origin.
### Why does this matter?
Our REST API may work in IntelliJ's HTTP Client while the browser refuses to make its response available to Swagger UI.

This happens because browsers enforce cross-origin restrictions. IntelliJ's HTTP Client does not apply those browser restrictions.

“Our REST API is working, but Swagger UI is running inside a browser.

Browsers have security restrictions for JavaScript requests between different origins.

We need the REST API to send response headers that tell the browser which origins and HTTP methods are allowed.

To do that, we'll create a CORS filter.”

## Step 7 — Create the CORS filter package

### What we're doing
We will use an IntelliJ file template to create a CORS filter.

This filter adds HTTP response headers that allow browser-based clients to communicate with the REST API.
### Where to go in IntelliJ IDEA
In the dmit2015-todo-restapi module, expand:

src/main/java

Right-click java → New → Package.

Enter:

`common.filter`

Then right-click the common.filter package and select New → File from Template.

Choose the DMIT2015 JAX-RS CORS Filter template.



`dmit2015-todo-restapi/src/main/java/common/filter/CorsProcessingFilter.java`
## Step 8 — Add CorsProcessingFilter.java

### Code explanation
| Code | Explanation |
| --- | --- |
| @Provider | Registers the class as a Jakarta REST provider. |
| @Priority(100_000) | Specifies the filter's priority. |
| implements ContainerResponseFilter | Makes this a filter that processes HTTP responses. |
| filter(...) | Runs when the server processes a response. |
| requestContext.getMethod() | Reads the incoming HTTP method. |
| OPTIONS | Handles the method commonly used for CORS preflight requests. |
| responseContext.setStatus(200) | Sets the response status to 200 for an OPTIONS request. |
| Access-Control-Allow-Origin | Specifies which origins are allowed. |
| "*" | Allows requests from any origin. |
| Access-Control-Allow-Headers | Lists request headers the server permits. |
| Access-Control-Allow-Methods | Lists HTTP methods permitted for cross-origin requests. |

### Important line from the instructor's demonstration
```java
headers.add("Access-Control-Allow-Origin", "*");
```


“This is the important part of the CORS filter.

We're adding an Access-Control-Allow-Origin response header with the value *.

That tells the browser that requests from any origin are allowed.

We're also specifying the request headers and HTTP methods that the client can use.

Once the filter is deployed, Swagger UI should be able to access our REST API.”

### What else does Swagger UI show?
When you execute a request, Swagger UI can display:
| Information | What it tells us |
| --- | --- |
| Request URL | Which REST endpoint was called. |
| cURL command | A command-line representation of the HTTP request. |
| Response code | Whether the operation succeeded or failed. |
| Response body | The data returned by the REST API. |
| Response headers | Additional information returned by the server. |
