# Part 1 — REST API Introduction and WildFly Setup

## Demo: Introduction to REST APIs with Jakarta RESTful Web Services (JAX-RS)

DMIT2015 — Part 1: Explore the Starter Project and Configure WildFly

## Introduction — What are we doing today?

“In this lesson, we're going to learn how to build a REST API using Jakarta RESTful Web Services.

Instead of building a web page that users interact with directly, we're building a backend service that other applications can communicate with using HTTP requests.

Our example is a To-Do application. Each to-do item has a task, information about whether it's completed, and some database fields.

Before creating the REST API endpoints, we'll explore the existing project, identify the entity and repository, examine the Jakarta REST configuration, and start WildFly using a different port.

Later, we'll implement the REST API methods and test them using HTTP requests.”

## Step 2 — Examine the TodoItem entity

### What we're doing


An entity represents the data that our application stores in the database.

### Where to go in IntelliJ IDEA

Open:

`dmit2015-todo-restapi/src/main/java/dmit2015/entity/TodoItem.java`

This file already exists in the starter project. Do not create or replace it.

### Code explanation

| **Code**        | **Explanation**                                  |
| --------------- | ------------------------------------------------ |
| @Entity         | Marks the class as a Jakarta Persistence entity. |
| @Id             | Identifies the primary key.                      |
| @GeneratedValue | Allows the database to generate the ID.          |
| task            | Stores the task description.                     |
| @NotBlank       | Prevents the task from being blank.              |
| done            | Stores whether the task has been completed.      |
| @Version        | Supports optimistic locking.                     |
| createTime      | Records when the item was created.               |
| updateTime      | Records when the item was updated.               |
| @PrePersist     | Runs before the entity is first saved.           |
| @PreUpdate      | Runs before an existing entity is updated.       |
| @Getter @Setter | Lombok generates getter and setter methods.      |

### What to understand

“Our to-do item has an ID, a task that needs to be completed, and a boolean property that tells us whether the task is done.

We also have a version field for optimistic locking.

Finally, we track the creation and update times for auditing.

These properties already exist, so we don't need to add them in this step.”

## Step 3 — Examine the TodoItemRepository

### What we're doing


The repository is responsible for performing database operations on TodoItem entities.

### Where to go in IntelliJ IDEA

`dmit2015-todo-restapi/src/main/java/dmit2015/repository/TodoItemRepository.java`

| delete(...)     | Deletes an existing entity.   |

| **CRUD operation** | **Meaning**      | **Repository example**   |

| Create             | Add a record     | add(...)                 |

At this stage, we're only reviewing the existing repository. No code changes are needed.

## Step 5 — Examine the WildFly port configuration

### What we're doing

The our REST API server will use port 8090 rather than the default port 8080.

This allows the REST API and a separate frontend application to run on different ports.

### Where to go in IntelliJ IDEA

Open:

dmit2015-todo-restapi/pom.xml

Find the `wildfly-maven-plugin` configuration.

### Existing starter code
```
<server-args>

    <server-arg>-Djboss.socket.binding.port-offset=10</server-arg>

    <server-arg>-b=0.0.0.0</server-arg>

</server-args>

<port>10000</port>
```

This configuration already exists in the starter project. Do not add it again.

### Code explanation

| **Code**                            | **Explanation**                                                 |
| ----------------------------------- | --------------------------------------------------------------- |
| \<server-args>                      | Contains arguments passed to WildFly when it starts.            |
| jboss.socket.binding.port-offset=10 | Increases WildFly's configured socket ports by 10.              |
| -b=0.0.0.0                          | Configures WildFly to bind to all available network interfaces. |
| \<port>10000\</port>                | Sets the management port used by the Maven plugin.              |

### WildFly port numbers

| **Service** | **Default port** | **With offset +10** |
| ----------- | ---------------- | ------------------- |
| HTTP        | 8080             | 8090                |
| HTTPS       | 8443             | 8453                |
| Management  | 9990             | 10000               |

“We're going to run our REST API on port 8090.

Normally, WildFly uses port 8080, but we want to reserve that port for our frontend client.

So inside the WildFly Maven plugin, we configure a port offset of 10.

That increases the HTTP port from 8080 to 8090.

We also configure the management port as 10000.”

## Step 6 — Start WildFly

### What we're doing

Now we'll start the REST API module and verify that WildFly launches.

### Where to go in IntelliJ IDEA

1. Open the terminal in IntelliJ IDEA.
2. Make sure you're inside the `dmit2015-todo-restapi` module, where its `pom.xml` is located.

### Command

```bash
mvn wildfly:dev
```

We're using the WildFly Maven plugin to launch our application.

Since we're using a newer WildFly version, the first startup might take some time.

Our server is configured to use HTTP port 8090, and we'll use that port when we begin testing the REST API endpoints.

In the next part, we'll begin building the REST API endpoints that allow clients to create, retrieve, update, and delete to-do items.”
