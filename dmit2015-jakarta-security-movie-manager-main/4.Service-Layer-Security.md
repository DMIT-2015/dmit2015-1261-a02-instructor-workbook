# Part 4 – Service-Layer Security and Custom Error Pages


## Introduction — What are we doing today?


> “In our previous lesson, we made Movie Manager a multi-user application.
>
> Sales users can see their own movies, while Administration users can see all movies.
>
> But there's still a security concern. What if someone tries to open another user's movie by changing the movie ID in the URL?
>
> Today, we'll add security checks directly inside our service methods to prevent unauthorized operations.
>
> We'll also create custom 404 and 500 error pages and test how our application handles those errors.”

## Step 1 — Add a role check when creating movies

### What we're doing

Our existing `addMovie()` method saves the logged-in username with each movie.

Now we'll add a role check to ensure that only Sales users can create movies.

### Where to go in IntelliJ IDEA

Open:

`src/main/java/dmit2015/service/MovieService.java`

Find the existing `addMovie()` method.

### Code

> “We already know how to save the logged-in username with a movie.
>
> We're now adding one additional check.
>
> Before creating the movie, the service verifies that the user has the Sales role.
>
> Even if someone bypasses the Create page, they still cannot create a movie through this service without the correct role.”

Add the following code at the beginning of the method, before the existing timestamp and username code:

```
if (!securityContext.isCallerInRole("Sales")) {
    throw new RuntimeException(
        "Access denied. Only Sales users can create movies."
    );
}
```


### Code explanation

| Code                              | Explanation                                          |
| --------------------------------- | ---------------------------------------------------- |
| `isCallerInRole("Sales")`         | Checks whether the logged-in user has the Sales role |
| `!`                               | Means NOT                                            |
| `throw new RuntimeException(...)` | Stops the operation if the user lacks permission     |
| `movieRepository.insert(movie)`   | Saves the movie only after the role check succeeds   |




## Step 2 — Restrict access to individual movie records

### What we're doing

In Part 2, we filtered the movie list so Sales users see only their own movies.

However, someone might attempt to open another user's movie directly by changing the ID in the URL.

We'll update `findMovieById()` to check ownership before returning the movie.

### Where to go in IntelliJ IDEA

Open:

`src/main/java/dmit2015/service/MovieService.java`

Find:

```
public Optional<Movie> findMovieById(Long movieId) {
    return movieRepository.findOptionalById(movieId);
}
```



> “Previously, we restricted which movies appeared in the list.
>
> Now we're protecting individual movie records.
>
> Administration users can access any movie.
>
> Sales users can access only movies that belong to them.
>
> If someone tries to open another user's movie by changing the ID in the URL, the service checks ownership and rejects the request.”


### Replace with

```
public Optional<Movie> findMovieById(Long movieId) {

    boolean isAdmin =
        securityContext.isCallerInRole("Administration");

    boolean isSales =
        securityContext.isCallerInRole("Sales");

    if (!isAdmin && !isSales) {
        throw new RuntimeException("Access denied.");
    }

    if (movieId == null) {
        return Optional.empty();
    }

    Optional<Movie> result =
        movieRepository.findOptionalById(movieId);

    if (result.isPresent() && !isAdmin) {

        String username =
            securityContext.getCallerPrincipal().getName();

        if (!username.equals(result.get().getUsername())) {
            throw new RuntimeException(
                "Access denied. This is not your movie."
            );
        }
    }

    return result;
}
```

### Code explanation

| Code                               | Explanation                                      |
| ---------------------------------- | ------------------------------------------------ |
| `isCallerInRole("Administration")` | Checks for the Administration role               |
| `isCallerInRole("Sales")`          | Checks for the Sales role                        |
| `!isAdmin && !isSales`             | Denies users without either role                 |
| `findOptionalById(movieId)`        | Retrieves the movie from the database            |
| `result.isPresent()`               | Checks whether the movie exists                  |
| `result.get().getUsername()`       | Retrieves the movie owner's username             |
| `username.equals(...)`             | Checks whether the logged-in user owns the movie |
| `throw new RuntimeException(...)`  | Rejects unauthorized access                      |



### Testing

Suppose Sales user A created movie ID `5`.

Log out and log in as Sales user B.

Try opening:

```
https://localhost:8443/movies/details.xhtml?editId=5
```

Use the actual movie ID and deployed application URL.

Expected result: The service denies access because the movie belongs to another user.


## Step 3 — Restrict movie updates to the owner

### What we're doing

We also need to prevent Sales users from updating another user's movie.

We'll check the movie's stored owner before saving any changes.

### Where to go in IntelliJ IDEA

Open:

`src/main/java/dmit2015/service/MovieService.java`

Find the existing `updateMovie()` method.


> “Before updating a movie, we're checking two things.
>
> First, the user must have the Sales role.
>
> Second, the movie must belong to that user.
>
> Notice that we retrieve the existing movie from the database to check its owner.
>
> We don't trust a username supplied by the form because that value could be manipulated.
>
> If the logged-in username doesn't match the stored owner, the update is rejected.”

### Replace with

```
public void updateMovie(Movie movie) {

    if (!securityContext.isCallerInRole("Sales")) {
        throw new RuntimeException(
            "Access denied. Only Sales can edit movies."
        );
    }

    if (movie == null || movie.getId() == null) {
        throw new RuntimeException("Invalid movie.");
    }

    Movie storedMovie = movieRepository
        .findOptionalById(movie.getId())
        .orElseThrow(() ->
            new RuntimeException("Movie not found.")
        );

    String username =
        securityContext.getCallerPrincipal().getName();

    if (!username.equals(storedMovie.getUsername())) {
        throw new RuntimeException(
            "Access denied. You cannot edit this movie."
        );
    }

    movie.setUsername(storedMovie.getUsername());
    movie.setCreateTime(storedMovie.getCreateTime());
    movie.setUpdateTime(LocalDateTime.now());

    movieRepository.update(movie);
}
```

### Code explanation

| Code                            | Explanation                                   |
| ------------------------------- | --------------------------------------------- |
| `isCallerInRole("Sales")`       | Requires the Sales role                       |
| `movie.getId()`                 | Identifies the movie being updated            |
| `findOptionalById(...)`         | Loads the original movie from the database    |
| `storedMovie.getUsername()`     | Retrieves the stored owner                    |
| `username.equals(...)`          | Verifies that the current user owns the movie |
| `movie.setUsername(...)`        | Preserves the original owner                  |
| `movie.setCreateTime(...)`      | Preserves the original creation timestamp     |
| `movieRepository.update(movie)` | Updates the movie after the security checks   |




### Testing

Log in as a Sales user and update one of your own movies.

Expected result: The update succeeds.

Then attempt to update another user's movie through an appropriate service-level test.

Expected result: The service rejects the update.



## Step 4 — Create custom 404 and 500 error pages

### What we're doing

We already created a custom 403 Forbidden page.

Now we'll create two additional error pages using the same approach:

- 404: Page Not Found.
- 500: Internal Server Error.

### Step 4A — Create 404.xhtml

Where: IntelliJ IDEA →

`src/main/webapp/WEB-INF/errorpages/`

Right-click the folder → New → File: from file template use: DMIT2015 Security Faces Custom 404 Error Page.


### Step 4B — Create 500.xhtml

In the same folder, New → File: from file template use: DMIT2015 Security Faces Custom 500 Error Page.




> “We're using the same approach as our custom 403 page.
>
> The 404 page is displayed when a requested resource cannot be found.
>
> The 500 page is used when the server encounters an internal error.
>
> These pages provide clearer messages without exposing unnecessary technical details.”

### Step 4C — Register the error pages in web.xml

Where: `src/main/webapp/WEB-INF/web.xml`

Find the existing 403 error-page mapping.

Leave it unchanged.

Add:

```
<error-page>
    <error-code>404</error-code>
    <location>/WEB-INF/errorpages/404.xhtml</location>
</error-page>

<error-page>
    <error-code>500</error-code>
    <location>/WEB-INF/errorpages/500.xhtml</location>
</error-page>
```



> “Creating the XHTML files isn't enough.
>
> We also need to tell WildFly which page to display for each HTTP error code.
>
> We're adding mappings for 404 and 500, just as we previously did for 403.”
